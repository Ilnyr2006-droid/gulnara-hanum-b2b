# Как включить отправку оптовых заявок

Сайт уже содержит две формы и серверную функцию, но **без подключения сервиса отправки письма никуда автоматически не уходят**. Это специально: пароли и ключи нельзя помещать в код страницы.

## Что нужно от владельца

1. **Домен сайта** (например, `example.ru`) или отдельный подтверждённый домен для отправки.
2. Аккаунт почтового сервиса **Resend** с подтверждённым отправляющим доменом.
3. Секретный `RESEND_API_KEY` и подтверждённый адрес отправителя `RESEND_FROM` — вводятся **только в настройках хостинга**, никогда в чат, HTML или публичный репозиторий.
4. Адрес получения уже задан: `gh150874@mail.ru` (при необходимости меняется через `LEADS_TO`).

## Vercel (вариант без отдельного сервера)

1. Подключить GitHub-репозиторий с содержимым этой папки (не включать настоящие `.env` и ключи; в публичном репозитории хранить только `.env.example` с безопасными заглушками).
2. Импортировать репозиторий как проект в Vercel. Корень проекта — папка с `index.html`, `package.json` и `api/lead.js`.
3. В Vercel → Project Settings → Environment Variables задать `RESEND_API_KEY`, `RESEND_FROM`, `LEADS_TO` и `PERSONAL_DATA_PROCESSING_APPROVED=false`. Отправка через Resend остаётся закрытой, пока владелец не подтвердит готовую политику и оператор, форму согласия, фактические сроки хранения, регион/условия обработки и используемую инфраструктуру. Установить `PERSONAL_DATA_PROCESSING_APPROVED=true` можно только после такого подтверждения. По умолчанию endpoint использует только `req.socket.remoteAddress` и игнорирует `X-Real-IP`; до публичного запуска проверьте, что `remoteAddress` соответствует посетителю, а не общему адресу платформенного прокси, иначе все посетители будут использовать общий лимит.
   - Не включайте `TRUST_X_REAL_IP`, пока не проверите, что входящий доверенный прокси для этого проекта заменяет `X-Real-IP`, установленный клиентом, и endpoint функции недоступен в обход этого прокси. Если обе проверки подтверждены, серверную переменную можно задать как `TRUST_X_REAL_IP=true`; функция примет заголовок только если это ровно один валидный IPv4/IPv6 адрес.
4. В Resend подтвердить отправляющий домен: добавить необходимые DNS-записи, дождаться подтверждения. Адрес `RESEND_FROM` должен использовать этот домен.
5. Повторно развернуть проект. Проверить вручную обычный прайс-запрос и запрос с несколькими позициями — сообщения должны поступить на указанную почту.

При доставке через Resend необходимо проверить соответствие обработки данных посетителей применимому законодательству, включая требования к локализации данных, прежде чем открывать публичный приём заявок. Переменная `PERSONAL_DATA_PROCESSING_APPROVED` по умолчанию отсутствует/равна `false`, и API возвращает 503 до вызова Resend, пока значение не равно строке `true`.

## Локальная проверка интерфейса

```bash
npm start
```

Откройте `http://127.0.0.1:3000`. Без переменных сервер вернёт статус 503 и предложит отправку через обычную почту — он не будет показывать ложное сообщение об успешной доставке.

## Собственный Node-сервер и Nginx

В этой поставке есть готовые примеры для текущей схемы:

- `deploy/gulnara-hanum-b2b.service` запускает Node только на `127.0.0.1:3015`;
- `deploy/gulnara-hanum-b2b-rate-limit.nginx` задаёт ограничение запросов в `http`-контексте Nginx;
- `deploy/gulnara-hanum-b2b-8095.nginx` проксирует только `/api/lead` и публикует каталог `public`.
- `deploy/gulnara-hanum-b2b-https.nginx.template` — шаблон для боевого домена: HTTP-редирект, TLS, API и будущий `sitemap.xml`. До подстановки канонического домена включать его нельзя.

Перед включением сайта создайте каталог `public` рядом с исходниками и скопируйте в него только `index.html`, `app.js`, `enhancements.css`, `privacy.html`, `robots.txt`, `llms.txt` и `assets/`. Не публикуйте в веб-каталоге `server.js`, `api/`, `lib/`, `.env.example`, `README.md` или `DEPLOY.md`.

Поместите секретные переменные в `/etc/gulnara-hanum-b2b.env`, задайте права `600`, затем установите unit и конфигурации Nginx. Node-порт не должен быть доступен извне. `TRUST_X_REAL_IP=true` допустим только когда Nginx перезаписывает `X-Real-IP` через `$remote_addr` и обращения к Node возможны лишь с loopback-интерфейса.

До настройки домена IP-адрес можно использовать только как технический preview. Нельзя принимать заявки посетителей по HTTP: для боевого приёма формы требуется HTTPS.

## Перед публикацией

- Утвердить юридическую информацию в `privacy.html`, сведения об операторе и согласие пользователей.
- Добавить общий WAF/антиспам и межинстансовое ограничение частоты запросов: лимитер в `api/lead.js` — best-effort и хранит состояние только в памяти одного экземпляра. Он ограничивает 10 000 уникальных IP-ключей; при заполнении новые ключи временно получают `429`, пока не истекут старые записи. Лимитер не координируется между инстансами и сам по себе не защищает от распределённого спама.
- При self-hosted развёртывании через приложенные Nginx-конфиги общий для всех запросов к этому серверу `limit_req` ограничивает `/api/lead`; Node при этом работает одним экземпляром за loopback. При нескольких Nginx-узлах или на Vercel этого недостаточно: подключите общий лимитер/WAF, учитывающий адрес посетителя от доверенного ingress. Не включайте доверие к заголовку IP, пока не подтверждены его перезапись платформой и закрытый прямой доступ к функции.
- Проверить, что хостинг/CDN не блокирует `OAI-SearchBot`; одного разрешения в `robots.txt` недостаточно для проверки доступности. Включение робота делает сайт подходящим для рассмотрения в ChatGPT Search, но не гарантирует показ или цитирование.
- Выбрать канонический HTTPS-домен и вариант хоста (`www` или без `www`), настроить редиректы с альтернативного хоста и `/index.html` на главную.
- После выбора домена добавить в `index.html` абсолютные `rel=canonical`, `og:url` и `og:image`; затем создать `sitemap.xml` только с каноническими публичными URL, исключив `privacy.html`.
- Добавить URL sitemap в `robots.txt`. Для self-hosted `server.js` также разрешить `/sitemap.xml` и установить XML MIME type; проверить, что выбранный хостинг отдаёт sitemap с HTTP 200.
- Убедиться в доставке писем на боевой адрес; отметить письмо как не спам.
- Подтвердить коммерческие условия, ассортимент и размерный ряд. Если планируется публиковать декларацию, проверить её номер из коммерческого предложения в официальном реестре и убедиться, что запись действует и относится к этим моделям; до такой проверки не указывать декларацию как действующую.
