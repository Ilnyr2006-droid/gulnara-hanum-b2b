# «Гульнара Ханум» — B2B-лендинг V6

Основа — согласованный исходный светлый HTML-дизайн V4.3. WebGL и декоративная нумерация отсутствуют. Без фреймворков и сторонних JavaScript-библиотек.

## Два способа запроса

1. **Быстрый запрос прайса** сразу после первого экрана: имя, email и согласие на обработку данных. Выбирать модели и указывать количество не требуется.
2. **Расчёт конкретной партии**: выбор нескольких моделей, количество от 10 шт. суммарно, имя и email; телефон и комментарий необязательны.

Обе формы отправляют JSON на `POST /api/lead`, а сервер формирует письмо на `gh150874@mail.ru`. Браузеру не передаются ключи почтового сервиса.

## Быстрый локальный предпросмотр

Нужен Node.js 20+. Установка npm-пакетов не требуется.

```bash
npm start
```

Откройте `http://127.0.0.1:3000`. Если просто открыть `index.html` по `file://`, внешний вид сохранится, но серверной отправки не будет. В этом режиме формы предложат открыть письмо через почтовую программу.

## Как включить реальную отправку

Реализована доставка через [Resend](https://resend.com) (HTTPS Email API). Она заработает **после** настройки сервера и подтверждения домена отправителя.

1. Зарегистрируйте отправляющий домен в Resend, подтвердите DNS-записи (SPF/DKIM) и получите ключ для отправки писем.
2. В панели вашего хостинга настройте **серверные** переменные окружения:
   - `RESEND_API_KEY` — секретный ключ Resend;
   - `RESEND_FROM` — отправитель с верифицированного домена, например `Гульнара Ханум <leads@your-domain.ru>`;
   - `LEADS_TO` — `gh150874@mail.ru`.
3. Разверните папку целиком на **Vercel** (корневая статическая страница и `/api/lead.js` как Node.js Function) либо на Node-сервере через `npm start`. Простого статического хостинга для серверной отправки недостаточно.
4. Сделайте реальную тестовую заявку **со своего email** и проверьте получение письма во «Входящих» и «Спаме».

**Текущее состояние:** ключ Resend не предоставлен, домен отправителя не подтверждён, фактическая доставка на боевой ящик не проверялась. Поэтому нельзя утверждать, что заявки уже доходят. До настройки интерфейс прямо сообщает об отсутствии доставки и предлагает ручное письмо.

## Защита и персональные данные

- Серверная проверка формата email, обязательного согласия, известных моделей, объёма партии и размера запроса.
- Проверка Origin и скрытое антиспам-поле; ограничение 5 запросов на IP за 15 минут *в рамках одного экземпляра приложения*. По умолчанию IP берётся только из `req.socket.remoteAddress`; клиентский `X-Real-IP` игнорируется. В serverless-среде проверьте, что `remoteAddress` уникален для посетителя: если это общий адрес прокси, посетители разделят один лимит.
- `X-Real-IP` можно включить серверной переменной `TRUST_X_REAL_IP=true` только если доверенный входящий прокси гарантированно заменяет этот заголовок, прямой доступ к Node endpoint закрыт, а поведение проверено для конкретного развёртывания. При включённом флаге принимается только одно точное значение IPv4/IPv6; список адресов через запятую и некорректные значения игнорируются.
- Карта лимитера ограничена 10 000 IP-ключами на экземпляр. Когда лимит достигнут, новые ключи получают `429`, пока не освободится место после истечения 15-минутных записей.
- Это локальный best-effort лимитер, он не координируется между экземплярами и **не гарантирует** защиту между ними. Для публичного запуска необходимы общий WAF/межинстансовый rate limit и подходящая антиспам-защита, например CAPTCHA/Turnstile.
- Сервер не пишет данные посетителей в базу; почтовый провайдер обрабатывает и хранит письма по своим правилам.
- `privacy.html` — **черновик**, который нужно согласовать и дополнить юридическими реквизитами и условиями обработки. Особое внимание: территориальные требования к хранению данных граждан РФ и использование международного почтового сервиса. До правовой проверки публичный приём персональных данных не запускать.

## Состав проекта

- `index.html`, `enhancements.css`, `app.js` — дизайн, две формы, UX.
- `api/lead.js` — обработчик заявок для Vercel / Node.
- `lib/lead.js` — валидация и отправка письма через Resend.
- `server.js` — локальный Node-сервер и возможность самостоятельного хостинга.
- `.env.example` — пример переменных окружения (НЕ копировать секреты в браузерный код).
- `privacy.html` — черновик информации об обработке данных.
- `tests/leads.test.js` — автоматизированные тесты серверной логики.
- `SEO_GEO.md` — текущая SEO/GEO-конфигурация, проверенные ограничения и шаги перед публикацией.

Отдельная пошаговая инструкция по включению отправки: **DEPLOY.md**.
